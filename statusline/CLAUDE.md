# statusline

`statusline/` is a standalone Cargo crate (sibling of `tomlctl`/`lumina`): a native renderer for **both** Claude Code status-line hooks, cutting per-refresh cost from ~1s of pwsh cold-start to single-digit milliseconds (the pwsh chain also amplified an MSYS shared-init poisoning that pinned "Git for Windows" CPU — see the repo memory on the `add_item` failure). One binary, two payloads, selected by argv:

- `statusline [--style full|min] [--icon <glyph>]` — the `statusLine` payload. `full` (default) is the original two-line colour-coded port of `~/.claude/statusline.ps1`; `min` is one line of bare text (`✻ dev-tools · hour 26% · week 7% · chat 31k · Opus 5 xhigh`). `--icon` belongs to `min` alone — passed to `full` or to `subagent` it exits 2 with `--icon applies to --style min only` rather than being silently ignored.
- `statusline subagent [--style tiers|rich]` — the `subagentStatusLine` payload; emits NDJSON `{"id","content"}` row overrides for the agent panel.

Layout details and the width tiers live in `README.md`. Structure: `cli.rs` (hand-rolled arg parsing — startup cost is the point), `payload.rs` / `subagent.rs` (wire types), `teamdata.rs` (per-teammate facts read off disk), `render/{full,min,agents}.rs` (all three are pure `payload -> String`), `fmt.rs` / `git.rs` / `ansi.rs` (shared). I/O lives in three files, not two: `main.rs`, `teamdata.rs` and `git.rs` — and none of it is reachable from a renderer. `main::git_facts` calls `git::branch` (which walks parents and reads `.git/HEAD`) and `git::diff_stats` (which spawns `git`, and only at `render::full::CHANGES_COLS` or wider), then threads both into `render::full::render` as parameters; `main::subagent_line` does the same with `teamdata::load`, and `main` itself performs one conditional disk write (the `STATUSLINE_DUMP` payload dump). That purity is the invariant `render/mod.rs`'s header states: a style that needs a new fact from outside takes another parameter, never a call into an I/O module.

Gotchas:

- **`full` is the unflagged default on purpose.** A `settings.json` that predates the `--style` flag keeps rendering exactly what it always did. Don't reorder that.
- **The subagent wire is camelCase** (`startTime`, `tokenCount`, `contextWindowSize`) while the main status-line payload is snake_case. `Task` carries `#[serde(rename_all = "camelCase")]`; the main `Payload` must not.
- **`min` emits no colour at all, `subagent` none beyond the agent-type badge, and `min` has uniform weight** — every character lands in the terminal theme's foreground (one colour, not a mix of greys), and `min` wraps the whole line in a single bold span rather than emphasising any segment. Resist re-adding a per-segment highlight for a saturated rate-limit window; it was tried and explicitly rejected. Three tests pin it: `min::the_line_is_one_bold_span_and_no_colour_at_all`, `min::a_saturated_window_is_no_louder_than_any_other_segment`, `agents::rows_carry_no_colour_beyond_the_badge`. The no-colour rule also dodges a real trap: Claude Code wraps unselected agent rows in its own `\x1b[2m`, and an SGR 0 in the row body cancels that for the rest of the line — which is why `min` closes its bold span with SGR 22 (`ansi::NOBOLD`), never a reset. `full` keeps its colours; it is the legacy style.
- **Never pick a statusline glyph with the Unicode Emoji property.** U+2733 (the reference page's icon) is `2733..2734 ; Emoji` in emoji-data.txt, so terminals render it from the colour-emoji font regardless of what the monospace face contains — wrong weight, wrong baseline, often double-width. The default is U+273B, which has no emoji property. `scripts/preview-icons.ps1` flags emoji codepoints (`!`) and, with `-Font`, codepoints the font lacks (`?` — Iosevka is missing U+2729–U+2730 and U+2735, for instance).
- **The subagent payload's `label` is `progressSummary || description`**, so it silently degrades to the first line of the orchestrator's prompt — markdown heading and all — whenever a task has no live progress summary. `render::agents` therefore treats `label == description` as *no activity*, and protects `name` (the task title) as the field that must never be dropped. Do not "simplify" that back to a plain label-over-name priority; it is the whole reason the rows are readable. Guarded by `a_prompt_derived_label_never_displaces_the_task_title`.
- **`subagentStatusLine` is read from the settings snapshot taken at session start.** The gate is `ft((c) => c.settings?.subagentStatusLine?.command !== void 0)`, so adding the key to `settings.json` mid-session leaves the agent panel on stock rows with no error anywhere — it needs a Claude Code restart. Same for `statusLine`. Diagnose with `claude --debug`, which logs the exit code and stderr of the first invocation — in this particular case the tell is that there is no invocation to log at all. Once the binary *does* run, the first-line diagnostics are its own: `--doctor` reads the payload off stdin, then writes what it resolved — version, mode, claude dir, subagents dir, parsed member count, the width and where it came from — to **stderr**, and exits 0 without drawing a row (stdout is the row protocol; nothing diagnostic may go there). `STATUSLINE_DUMP=<path>` writes the raw stdin payload verbatim to that path before rendering, so a field report becomes a deterministic offline repro; a failed write is ignored, like every other failure in this binary.
- **Never read `teams/<team>/config.json` on a refresh tick.** It carries the same `agentType` the 330-byte `subagents/*.meta.json` files do, but embeds every member's full dispatch prompt — ~110 KB for a team of eleven. `teamdata.rs` reads the meta files and the tiny inbox JSONs instead, and caps at 64 members. The meta files must all be enumerated — a member's name lives inside its file, so there is no cheaper way to learn whose it is — but the second read is not free work: `load` takes the set of names the panel is about to draw and counts an inbox only for those, so a session whose panel shows three of eleven teammates pays three inbox reads, not eleven.
- **Agent-panel row priorities are load-bearing, not cosmetic.** `P_TOKENS`/`P_MSGS` sit at or above `P_PROTECTED`, so they are never shed and the *name* is clipped to make room for them; everything else sheds lowest-first. Reordering these silently changes which field disappears on a narrow pane. `every_tier_fits_its_budget` only checks widths — the ordering is pinned by three tests: `tiers_clip_the_activity_then_shed_by_priority` (hand-computed widths at each transition), `the_shed_order_holds_at_every_width` (the suffix-and-monotonicity property those literals sample, over the full width range), and `the_unsheddable_class_is_exactly_the_two_counts_and_the_title` (which pins *which* segments sit above the protected floor, so an insertion that silently crosses it fails).
- **`columns` in the subagent payload is already the usable body width** — Claude Code subtracts the pointer/bullet/tree gutter (`terminalColumns - 4`) before handing it over. Don't subtract again.
- **Empty subagent output means "keep the defaults"**, so an unparseable payload degrades silently to stock rows rather than blanking the panel. The main line degrades to the bare label `Claude` instead.
- **Width accounting is `char`-count, not east-asian width.** Adequate because Claude Code truncates as a backstop, but a wide-glyph label will render one tier tighter than budgeted.

Commands:

- `cargo test --manifest-path statusline/Cargo.toml` — build + run the unit tests (`every_tier_fits_its_budget` property-checks the width tiers over `cols 1..=95`, across six row fixtures × both subagent styles, asserting `width <= cols` unconditionally) plus `tests/cli.rs`, which drives the installed-shape binary through `CARGO_BIN_EXE_statusline` to pin the contracts no unit test can see: no trailing newline on stdout, exit 2 with a silent stdout on a usage error, exit 0 on `--help`/`-V`, and `--doctor` writing nothing at all to stdout. Run that file alone with `--test cli`
- `cargo clippy --manifest-path statusline/Cargo.toml --all-targets` — lint
- `cargo install --path statusline` — install `statusline.exe` onto PATH; `~/.claude/settings.json` points `statusLine.command` and `subagentStatusLine.command` at it (forward slashes — Git Bash eats backslashes in a `command` path)
- `statusline --list-styles`, `statusline subagent --columns 40 < payload.json` — eyeball a tier by hand
- `statusline subagent --doctor < payload.json` — report the resolved claude dir, subagents dir, parsed member count and width source on stderr, then exit without drawing a row (`STATUSLINE_DUMP=<path>` captures that payload in the first place)
- `scripts/preview-icons.ps1 [-InSitu] [-From <cp>] [-To <cp>] [-Font <ttf>] [-Binary <exe>]` — browse candidate glyphs in the terminal that has to render them. `-InSitu` shells out to the cargo-installed `statusline.exe` and throws if it is missing; `-Binary` points it at an uninstalled build (`statusline/target/release/statusline.exe`) or a non-default install instead
