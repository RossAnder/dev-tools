# glimpse

`glimpse/` is a standalone Cargo crate (sibling of `tomlctl`/`statusline`, own `Cargo.lock` and `target/`): a ratatui TUI that draws a flow's task DAG, checkpoints and running agents from a `tasks snapshot` it builds in-process through the `tomlctl` library (a path dependency, `default-features = false`), beside item surfaces for the review, optimise, plan-review and backlog ledgers and an Inbox of user input records and agent questions, plus the Claude Code hook and herdr pane plumbing that feeds and opens it. Usage, keys, config keys and the data flow live in `README.md`.

Write model: glimpse writes two things and nothing else. Control fields — status dispositions with their companion text, and review/optimise `severity`, `effort` and `category` — go through the tomlctl library's silent ledger facade, compare-and-set guarded on the values glimpse displayed. Free text (captures, change requests, notes) and answers to agent questions are appended as records to `.claude/inputs.toml`, whose contract is the `flow-contract-user-inputs` skill's; agents act on them and make any content edit themselves.

Structure: `cli.rs` (hand-rolled parser; `hook` runs on every subagent event, so start-up cost matters), `main.rs` (wiring only). Data in: `watch.rs` (one `notify` watcher over `.claude/flows` recursively, `.claude` and each existing flow-less ledger dir non-recursively, classifying events into wakes), `source.rs` (the watcher-woken fingerprint poller and its ledger and input feeds) with `source/mode.rs` (watching vs polling, the safety clock, per-scope miss streaks) and `source/scan.rs` (the stats and the in-process snapshot, ledger and flow-list fetches), `flows.rs` (`tomlctl::flow_list_matching` over the poller's task-store scan, freshest flow), `model.rs` (snapshot types and the `Index` views look rows up through), `ledger.rs` (ledger rows, status classes, filter, group-by and sort), `diff.rs` (change sets between snapshots), `transcript.rs` (incremental JSONL tail for the activity panel). State: `app.rs` (selection, overlays, follow, flashes; never draws, never spawns), `surface.rs` (the digit-key surfaces and per-surface cursor, marks and arrivals), `actions.rs` (the transitions and classify edits each ledger offers, as forms and write requests), `form.rs` (modal text, select and multi-select fields), `keys.rs`, `config.rs`, `theme.rs` (colour tokens → styles), `state.rs` (layout choices saved between runs). Drawing: `runtime.rs` (event loop and `--once`), `view/` (header, layers, ego, details, activity, selector, legend, markdown, items, inbox, form), `diagram/` (the hand-written layered layout: `reduce` → `order` → `position` → `route` → `paint`). Out to the world: `writer.rs` (the serial writer thread), `hook.rs`, `pane.rs`, `herdr.rs` (herdr CLI wrapper), `setup.rs`.

Gotchas:

- **Hook edits are normally hot-reloaded.** Claude Code's settings watcher picks up the hooks `glimpse setup` merges into a running session; a restart is the fallback when they do not fire, not a step of setup. That is what setup's closing line says, and it should keep saying it.
- **The Claude Code hooks are exec form on purpose; the Codex hooks cannot be.** `setup` writes `"command": "<glimpse path>", "args": ["hook"]`, so Claude Code spawns the binary directly; a shell-form command would start Git Bash on Windows for every subagent event. `is_glimpse_hook` treats a shell-form `glimpse hook` entry as already installed and leaves it alone. Codex has no `args` field and runs every hook through the session shell (PowerShell, cmd or sh), so its `<CODEX_HOME>/hooks.json` entries are the line `<glimpse path> hook --harness codex`; no quoting survives all three shells, so setup refuses a path that needs any.
- **New Codex hooks are inert until trusted.** Codex asks at its next start and runs nothing before the user accepts. It also warns when both `hooks.json` and `[hooks]` in `config.toml` define hooks; setup writes only `hooks.json` and notes the clash.
- **Async hooks are silent.** Claude Code neither waits for an async hook nor reads its exit code, stdout or stderr, so `glimpse hook` never prints and always exits 0. When agents stop appearing, read `<claude dir>/glimpse/hook.log` first: every failure is one timestamped line there, including an `agents record failed:` from the in-process recorder. Both harnesses log there, and a usage error in the hook's own arguments is logged too, still with exit 0. The log is truncated to empty once it passes `LOG_CAP` rather than rotated.
- **Never run `glimpse setup` without `--dry-run` while testing.** It edits the real `settings.json`, herdr `config.toml` and Codex `hooks.json`. `tests/cli.rs` points every config location, `CODEX_HOME` included, into a per-case sandbox, names a `herdr` that does not exist and removes `TOMLCTL_ROOT`, so no case touches the user's files; keep new binary-level cases inside that sandbox.
- **Transcripts follow a version anchor.** The JSONL line shape `transcript.rs` reads is observed, not documented; its module doc records the Claude Code version and date it was checked against. A renamed field degrades to an empty activity panel rather than an error, so a panel that goes quiet on a live agent starts there, and a re-check updates that anchor.
- **The diagram layout is cached on `(topology_hash, orientation, show_implied)`.** `Index::topology_hash` covers only task ids and both edge sets (FNV-1a, stable across Rust releases), so a status change reuses the layout and only `paint` re-runs. A layout input added to `diagram/` that is not in that hash will go stale on screen; add it to the hash in the same change.
- **herdr has no focus-by-id.** `pane::ensure` focuses an existing pane by moving from the origin in the direction the two rects imply, which works only when they are adjacent; otherwise the pane is reused unfocused. `herdr pane run` types text plus Enter into the pane's shell (pwsh here) rather than spawning a process, which is why `launch_line` quotes for pwsh. Popup keybindings go through `cmd.exe /d /c` instead (`/bin/sh -c` on Unix), so `setup::popup_command` quotes differently; do not merge the two helpers.
- **One pane per tab is enforced by a lock file**, `<claude dir>/glimpse/pane.lock`, so two hooks firing together cannot both split. It is an OS file lock on a persistent file, so a holder that dies releases it. An existing pane is found without the lock; only the split path takes it, and re-lists under it before splitting.
- **Never verify integrity sidecars from glimpse.** tomlctl writes the sidecar and the TOML as two renames, so a check from the poller can land between them. A torn read surfaces as a failed fetch and is retried on the next wake or safety tick, or after `RETRY_AFTER` if neither comes. glimpse's own writes keep the sidecars current, because the facade writes through tomlctl's locked mutation path.
- **Every write goes through the tomlctl facade on the writer thread.** A facade call can wait up to 30 s for the ledger lock, so it never runs on the UI thread or the poller, and glimpse never edits a ledger, `backlog.toml` or `inputs.toml` any other way. The facade refuses with `root mismatch` when tomlctl's process root differs from glimpse's, since the lock directory derives from that root; two writers must agree on it.
- **No optimistic model updates.** A submitted write marks its rows `saving`; the rows change only when the feed's next read shows the change, and the mark clears there or on an error or stale-skip outcome, which shows as a footer notice. Undo restores exactly the fields glimpse wrote, guarded on their still holding glimpse's values.
- **Control fields only.** glimpse never writes item content (`summary`, `description`, `file`, `symbol`, `instances`, `evidence`), ids, `rounds`, `dedup_id`, `first_flagged`, `depends_on`, or any backlog field but its triage status, and never bumps a review, optimise or plan-review ledger's `last_updated`, which the apply freshness gate compares against commit dates. A new editable field needs a facade verb that owns its validation, not a wider form.
- **Free text goes to the input store.** Anything the user types that is not a control field's companion text — a capture, a change request, a note, an answer — becomes a record in `.claude/inputs.toml` for an agent to act on; an input record is undone by withdrawing it.
- **The watch only wakes; the fingerprints decide.** `flows_fingerprint` re-stats `tasks.toml` and `context.toml` on every scan for each flow cached with a task store; the directory mtime gates only flows without one, re-statting them when it moves or when the flow has no cached entry. The split exists because an in-place save never moves the directory mtime (NTFS and ext4 alike), and on Windows the mtime the enumeration reports can lag even a non-rename file creation by seconds; a rename, which is how tomlctl creates a store, moves it at once. For a store-less flow an in-place creation is seen only because `Poller::evict` drops the woken flow's `flow_stats` entry before the tick; `Wake::All` and `Wake::Rewatch` clear the whole cache and force a fetch. Repo and scope wakes (`backlog.toml`, `inputs.toml`, a flow-less ledger) evict only the feeds they name, never the flow caches or the task fingerprint, and each feed is re-read only when its `(mtime, len)` moves. A new change detector has to be reachable from an eviction or the every-scan re-stat the same way. The `watch::start` callback runs on notify's event thread and must never block: it only classifies and posts `Control::Wake`.
- **A silent watch scope falls back to polling for good.** Each watch scope — `.claude/flows`, the repo files under `.claude`, and each flow-less ledger dir — keeps its own miss streak, because on Windows each watched path has its own handle and one can die while the others keep reporting. A safety tick or a wake tick that finds a change in a scope that did not itself wake counts a miss against that scope; a tick forced by `Wake::All` or `Wake::Rewatch` counts nothing. When any scope reaches `MISS_LIMIT` (two) the watcher is dropped and glimpse polls every `poll_ms` for the rest of the session. Only a scope's own wake resets its streak, so a busy scope cannot vouch for a dead one; a clean tick neither counts nor resets, or a dead watch under sparse writes would never be caught, and a newly started watch begins at zero. The safety clock (`SAFETY_TICK`, 10 s while watching) moves only when a safety tick runs or the period changes, so frequent wakes cannot hold it off. A flow-less ledger dir created after the watch started arrives as `Wake::NewScope`, which adds one non-recursive watch for it on the existing watcher and rescans it once; a path is never watched twice, since a duplicate watch on Windows leaks a handle and doubles events. On Windows this is the only dead-watch detector: notify 8.2's `ReadDirectoryChangesW` backend unwatches on error without delivering an `Err` or a `Rescan`, so `Wake::Rewatch` and `Wake::All` never fire there. A watch that failed to start is retried at polling ticks under a backoff doubling from `poll_ms` to `WATCH_RETRY_MAX` (60 s), reset when a start succeeds; a missing flows root is re-probed every tick and costs no backoff. `Access` events never wake it: inotify reports glimpse's own reads.
- **glimpse links its own copy of tomlctl.** A change to tomlctl's snapshot, flow-list, ledger facade, `inputs` or `agents record` code reaches glimpse only when glimpse is rebuilt, so after changing tomlctl run `cargo install --path glimpse` as well as `cargo install --path tomlctl`. glimpse is also a second writer of `agents.toml`, of the review, optimise and plan-review ledgers, of `backlog.toml` and of `inputs.toml`, beside the orchestrator.
- **On Windows the watch pins the repo's directories.** The watch handles stop the repo, its `.claude` directory or a worktree being renamed or moved while glimpse runs ("Access denied"; deleting still works). Close the glimpse pane first.
- **Shape decisions assume a cell aspect.** Orientation and panel side compare pixel aspect ratios, so they need a cell's height over its width. `crossterm::terminal::window_size` supplies it on Unix terminals that report pixels; Windows (ConPTY) reports none, so there it is the config's `cell_aspect`, and a font far from the 2.2 default (Iosevka is ~2.5) makes `auto` choose the wrong side. Check that value before touching the thresholds.
- **Colours come only from `theme.rs` tokens.** A view never names a `Color` or reaches for `Modifier::DIM`; it takes a `Theme` field, and a new UI feature worth colouring gets its own element token in `TOKENS` defaulting to a palette token, plus a row in the README table and, if it is a mark, in `view/legend.rs`.
- **`Release` key events are dropped** in `keys::map`: Windows reports both edges of every key, which would apply each action twice. `keys::mouse` does the same for clicks, acting on the press only.
- **Mouse capture reports every pointer move.** An event that maps to no action must return `Step::Nothing` and skip the redraw, or hovering repaints continuously. Capture is switched off before `ratatui::restore` on exit and by a panic hook `runtime::capture_mouse` chains ahead of ratatui's; `--once` never captures.
- **Mouse hits read the last frame.** `view::render` writes `App::regions`, the details scroll bounds, the resolved density and the layers column width back into `App`; `keys::mouse` and the actions that clamp or step from those values see what was last drawn, not the current terminal size.
- **The traversal trail survives only `Navigator::walk`.** `App::select` empties `App::trail` on any change, and `move_selection` puts back the trail the walk returned. A new way to change the selection must go through `select`, or the ego view will walk a side the user never crossed into; `ego` also re-checks the trail against each snapshot and drops the part that no longer leads to the selection.
- **An idle glimpse's own threads do no periodic work beyond the safety tick.** notify's Windows backend thread is not one of them: it waits in `WaitForSingleObjectEx` with a 100 ms timeout, so it wakes about ten times a second even when nothing changes. The main loop blocks on its channel without a timeout unless `App::tick_interval` returns one: 1 s while `needs_tick` (a live flash, or a running agent whose clock is advancing), 30 s while any agent is running at all, so a stale agent that resumes is noticed. Anything new that changes on screen with time alone has to be reflected there, or it will freeze between snapshots. The activity panel's transcript is not on that tick: the runtime sends the panel's target with `Host::set_tail`, the poller re-reads it every `TICK` on its own thread, and the result arrives as `Event::Tail`, so the UI thread does no file I/O for it.

Commands:

- `cargo test --manifest-path glimpse/Cargo.toml` — unit tests plus `tests/cli.rs`, which drives the built binary through `CARGO_BIN_EXE_glimpse` for exit codes, stream discipline and on-disk effects; run that file alone with `--test cli`
- `cargo clippy --manifest-path glimpse/Cargo.toml --all-targets` — lint
- `cargo fmt --manifest-path glimpse/Cargo.toml -- --check` — the pre-commit hook runs this whenever a `glimpse/**/*.rs` path is staged
- `cargo install --path glimpse` — install onto PATH. The hooks and keybinding store glimpse's absolute path, and `setup` skips any entry that already names glimpse, so if the binary moves, fix those entries by hand; rerunning setup changes nothing
- `glimpse --once --snapshot glimpse/tests/fixtures/snapshot.json --size 110x40 [--view diagram]` — render one frame headlessly, with no terminal and no flow files read; `--once --slug <slug>` does the same against a live flow
- `glimpse setup --dry-run` — show what setup would add, writing nothing
