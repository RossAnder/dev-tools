Verdict: The orchestrator hand-builds three things. The launch args come from rows, specs and premise verdicts (run-milestone.md:136-191). The reproduce units come from `[[finding_links]]` and `[[reproductions]]` (findings.md:67-96). The gate list comes from `milestones.gates` and `accept[].writes_build` (drain.md:225-264). No verb emits any of them whole. All three can be derived from stored fields, with two gaps: nothing stores which rows a launch dispatched (plan/schema.rs:248 `Run` has no task list), and nothing stores which gates are held back or how to probe one (tasks/schema.rs:320 `MilestoneSpec.gates` is a bare `Vec<String>`). Fill both gaps with additive fields, then use three emit verbs, an `Accept.covered_by` string and `plan probes --emit --gates`.

Proposed shapes:

1. **Launch args.** Add `tomlctl tasks ready --slug <s> --checkpoint <id> --launch-args [--max-parallel N]`, or a sibling verb `tasks launch-args`. It prints `{args:{slug,milestone,root,max_parallel,tasks:[{id,executor,needs,files}]}, args_sha256, dropped:[{id,reason,because}]}`. It applies the six rules of run-milestone.md:147-152, the premise table (run-milestone.md:118-132, with the skip reasons from `premise_skip_reason`, plan/probes.rs:168) and the started-row exception for anchor premises (findings.md:37-44). The `dropped` reasons are `withheld:<n>:<i>:<verdict>`, `needs-withheld:<n>`, `executor:<tool|clerk>`, `no-files`, `need-not-done:<n>:<status>` and `not-pending`. A `plan run start --args-file <path>` that hashes the file itself would also remove the `sha256sum` pipe.
2. **Reproduce units.** Add `tomlctl review reproduce-units --flow <slug> --milestone <id> <store-flag> [--since-launch]`. It prints the whole args object for one store: `mode`, `run_dir`, `store`, `flow`, `milestone`, `round` and `units`, applying the highest-id-owner rule. It also prints `stores:[...]` when the milestone links others, so the orchestrator can loop over them. The later-pass filter needs the dispatched ids (F3).
3. **Gate list.** Add `tomlctl tasks gate-list --slug <s> --checkpoint <id>`, or `plan gate --milestone <id>`. It prints `{commands:[{command, source:"gate"|"accept:<task>:<i>", held}], skipped:[{task, accept, reason:"covered_by <gate>"|"duplicate"}]}` in the order drain.md:247 already fixes. It could also print the verification prompt text directly with a `--prompt` template.
4. **Covering gate (B-56a8a9ff).** Add an optional `Accept.covered_by: String`, empty by default, holding the exact command of a gate on the row's own milestone. Write it at Write time through `tasks add-many` / `tasks update --ndjson`. `plan check` reports a new error class, `plan/accept-cover-unknown`, when the string matches no gate of the row's checkpoint. That covers a later `plan milestone update --gate`, which replaces the whole list, and a row moved to another checkpoint. The gate list drops a covered entry. The worker view prints `Run by: gate <cmd>`.
5. **Gate probe (B-14586282).** Add `plan probes --emit --gates --milestone <id>` and its `--record`. It emits one line per gate that has a stored probe command and records the verdicts as `holds`, `fails` or `broken`, reusing the premise verdict rules. Run it at Prove and in the implement-v2 pre-flight. The probe command needs storing beside the gate (F5).
