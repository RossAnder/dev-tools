Verdict: The 400 comes from passing `schemas.verdict_return` (whose top-level `allOf` is emitted at tomlctl/src/review/schema_out.rs:326) bare to agent() at claude/workflows/review-v2.js:220/226 and plan-v2-review.js:213; reproduce units are one Opus verifier per task with no route data (review-v2.js:100-143); plan-review verifiers are one per critical/major defect by the routing at review-v2.js:295-313, a documented envelope; the ripple cell is thin because review-sweeper step 6 builds NAMES from `git diff` over untracked flow files; a later reproduce round cannot read an earlier round's payload (run_dir carries the round, findings.md:93), only a same-round relaunch shares it.

## Answer

1. **allOf.** The engine runs `tomlctl review schema verdict-return` (review-v2-engine/SKILL.md:138, plan-flow.md:73) and hands it through as `schemas.verdict_return`. `verdict_return()` encodes the unblocks/fix_sketch pairing as `if/then` rules under a top-level `allOf` (schema_out.rs:309-327). Batches work because review-v2.js:175-179 nests the schema under `verdicts.items`, so the `allOf` is not at the top level. Single and panel verifiers (review-v2.js:220, 226) and plan reverify (plan-v2-review.js:213) pass it bare. The pairing is enforced again at write time by `review verdict`'s validator (the schema_out.rs tests at the `refused(...)` asserts, around :520-560), so dropping it from the return schema loses no guarantee. Smallest fix: strip top-level `allOf`/`anyOf`/`oneOf` from `verdict_return` once in each script before use. The other option is to stop emitting it in schema_out.rs, which means rewriting the test that reads `schema["allOf"]` (:536).
2. **Reproduce units.** The engine assembles units by hand (findings.md:72-76) as `{task, files, findings}`. The script validates them (review-v2.js:62-72) and launches one `review-verifier` per unit (`runUnit`, :115-140; `parallel` at :143). Units carry no kind or route, so the script cannot tell which ones grep can decide. Routing those to `review-checker` needs the five changes below, so it is `needs-plan`, not one edit.
3. **Plan-review verifiers.** `routeCell` (review-v2.js:295-313) launches one `verifyOne` per verifier-routed defect that is not a minor at quick/standard, three seats per panel, and one batch each for a cell's minors and cleanups. Plan cleanups always route to the verifier (fields.rs:1421). The plan wrapper adds one `reverify` agent per id (plan-v2-review.js:378). One verifier per critical or major defect is the documented depth envelope (review-v2-engine/SKILL.md:219; agent-waves.md:119-120), so batching per cell changes a contract as well as the script.
4. **Ripple cell.** `tomlctl review` proposes it as a floor lens (ripple.md `activation = "floor"`; compose.md:82 forbids dropping one). The lead copies it into the wave (plan-v2-review.js:305, 318), and it runs as a `review-sweeper` cell (review-v2.js:181-184, 271-272). Sweeper step 6 (review-sweeper.md:29) builds `NAMES` from `git diff <base>..HEAD -- <slice>`. On an unapproved plan the slice (`brief.md`, `design/*.md`) is untracked, so the diff is empty and nothing gets swept. The run artifacts show this directly (below). `tomlctl sweep` itself does list untracked files (repo_files.rs:12, `--others`), so the search tool is not the gap; the missing NAMES are.
5. **Stale payload (B-72a04d82).** The payload path is `${run_dir}/payloads/reproduce-<task>.ndjson` (review-v2.js:101), and `run_dir` is `.review-v2-runs/apply-<slug>-<id>-<round>` (findings.md:93). The round is computed as the highest recorded round + 1 (findings.md:84-88). Step 6 writes a row for every finding in the round, as a verifier row or an orchestrator row (findings.md:139), unless the finding is parked, so every later round gets a fresh directory. Only a same-round relaunch (findings.md:113, step 5) reuses the directory. That relaunch uses the same round number on an unchanged tree, and `review reproduce` replaces rows on `(finding, flow, milestone, round, by)` (review-verifier.md:57). A stale payload therefore cannot be recorded against the wrong round or tree. Its real cost is Write-tool friction: overwriting an unread existing file fails, so the relaunched verifier must Read the old payload first. Smallest fix: give a step-5 relaunch its own `run_dir` suffix (for example `-<round>-relaunch`). That is a prose change to findings.md only.
