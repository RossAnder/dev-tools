## Context

[ADR-0006](../adr/0006-git-execution-companion.md) (accepted 2026-06-09) splits lumina into a record-only **control plane** (server/store) and a git-executing **execution plane** (the Companion), connected by a wire protocol. Step 1a ([binary-jumping-yao](binary-jumping-yao.md), landed) carved the four-member workspace and left `lumina-protocol`/`lumina-companion` as stubs. This plan is **Step 1b**: populate those stubs with the git-execution plane and wire execute→record through the server, exactly as the ADR decided — `GitBackend` (companion-internal, shell-git v1), coarse intent→outcome wire types, companion-dials-server WebSocket with heartbeat, server-side merge-lease, and the ground-truth-SHA-driven `record_worktree_merge`/`record_task_commits` inversion. The ADR's rejected options are settled; this plan implements, it does not relitigate.

Vocabulary per `lumina/CONTEXT.md` § "Control & execution planes": Control plane, Execution plane, Companion, Merge supervisor (the supervisor agent is Step 2+; Step-1 conflict handling is abort + surface to the caller).

## Scope

- **In scope**: `lumina-protocol` wire types; `lumina-companion` as lib+bin (GitBackend trait + neutral types, ShellGit impl, quarantined `run_git`, FakeGitBackend, executor, WS connection loop); server companion seam (registry, in-memory merge-lease, `/api/companion/ws` endpoint); one new MCP tool `execute_worktree_merge` + HTTP mirror (count gate 84→85); a read-only repo query for `must_remain_reachable` derivation; `lumina serve --with-companion` co-launch; cross-plane e2e test; root + `lumina/` CLAUDE.md doc updates (deferred to implementation time by the ADR).

- **Affected areas**: `lumina/protocol/`, `lumina/companion/`, `lumina/server/` (companion seam, http, mcp, cli), `lumina/core/src/repo/worktrees.rs` (one read-only fn), `CLAUDE.md`, `lumina/CLAUDE.md`.

### Transport & process lifecycle (Agent-1, research-lite)

1. **tokio-tungstenite 0.29 client**: `connect_async(url) -> (WebSocketStream<MaybeTlsStream<TcpStream>>, Response)`; stream impls `Stream` + `Sink<Message>`; split via `futures_util::StreamExt::split`. [A — Context7 /snapview/tokio-tungstenite]
2. **`Message::Text` carries `Utf8Bytes` (not `String`)** in tungstenite 0.26+/axum 0.8 — both sides; `&Utf8Bytes` derefs to `&str` for `serde_json::from_str`. [A — tungstenite CHANGELOG, axum#3082]
3. **axum 0.8 WS server**: `WebSocketUpgrade` extractor + `ws.on_upgrade(...)` on `Router<AppState>`; axum auto-replies Pong to client Pings; dead-client detection = server's own Ping + deadline, or `recv() → None/Err`; canonical split + mpsc-fed send-task pattern. [A — Context7 /tokio-rs/axum]
4. **Heartbeat idiom**: `tokio::select!` over `interval.tick()` (send Ping) vs `read.next()`; reset deadline on any inbound frame; redial when elapsed. [B]
5. **`kill_on_drop(true)` fires only on in-process `Child` drop — NOT on parent crash**; tokio has no job-object/process-group tying. v1 co-launch = kill_on_drop for graceful exit + companion self-terminates when its WS drops. [A — tokio Command docs]
6. **`backoff` crate is unmaintained (RUSTSEC-2025-0012)** — hand-roll `min(base*2^n, cap)+jitter` rather than adding `backon`. [A]
7. **clap 4 derive**: top-level `#[arg(long)] with_companion: bool` + `companion_bin: Option<PathBuf>` coexist with `command: Option<Subcommands>`; avoid `args_conflicts_with_subcommands`; gate flag relevance in code. [B — clap#5353]

### Git CLI semantics for the shell backend (Agent-2, research-lite)

8. **`git worktree add <path> -b <branch> <start>`** is atomic; refuses if branch checked out elsewhere or path occupied. **`worktree remove`** refuses on dirty (needs `--force`); main worktree never removable. [A — git-worktree docs]
9. **`worktree list --porcelain -z`**: NUL-terminated records (`worktree <path>` / `HEAD <oid>` / `branch refs/heads/<n>` / `detached` / `locked`); `-z` avoids Windows path-quoting. [A]
10. **Conflict detection**: `git merge` exits 1 on conflict; reliable classification = `git rev-parse -q --verify MERGE_HEAD` present AND `git ls-files -u` non-empty; else non-zero ⇒ "other failure". **`merge --abort` is reliable iff the worktree was clean pre-merge.** `--no-ff` forces a true merge commit. [A — git-merge docs]
11. **`git merge` merges only INTO the branch checked out in the cwd, and a branch cannot be checked out in two worktrees.** The integration branch needs a dedicated checkout the merge runs in. [A — git-merge/git-worktree docs] → User Decision 1.
12. **Reachability**: `git merge-base --is-ancestor <sha> <tip>` exit 0=ancestor / 1=not / >1=error; existence pre-check `git cat-file -e <sha>^{commit}`. [A — git-merge-base docs]
13. **State derivation**: `status --porcelain=v2 --branch` — clean ⟺ zero non-`#` lines; detached ⟺ `# branch.head (detached)`. [A]
14. **Scripting hygiene**: env `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `GIT_CONFIG_NOSYSTEM=1`, `LC_ALL=C`; flags `-C <dir>`, `-c core.quotepath=false`, Windows `-c core.longpaths=true`; commit identity via `-c user.name/email` env or flags (set author + committer). [A; longpaths-per-call = C — verify on target git build]
15. **async-trait 0.1.89 traits are object-safe**: `Box<dyn GitBackend + Send + Sync>` works; default `Send` bound on returned futures. [B]

## Approach

**Three layers, each mirroring an existing repo pattern.**

1. **`lumina-protocol`** (serde + serde_json only, no internal deps — the narrow waist): `PROTOCOL_VERSION: u32 = 1`; `RequestId` (u64); internally-tagged enums `ServerToCompanion::IntentRequest{id, intent}` and `CompanionToServer::{Hello{protocol_version, companion_id, repo_root}, Outcome{id, outcome}}`; `Intent::{CreateWorktree, RemoveWorktree, CommitCheckpoint, MergeWorktree{source_branch, target_branch, must_remain_reachable: Vec<Sha>, no_ff: bool}, Reconcile}`; one coarse `Outcome` per intent (`Merged{merge_sha, fast_forward}` | `AlreadyUpToDate{tip}` | `Conflicted{paths}` | `Failed{kind, message}`; `Reconciled{worktrees: Vec<WorktreeSnapshot>, target_tip}`). Protocol types are wire-level — distinct from both core domain types and GitBackend types (server translates core↔protocol; companion translates GitBackend↔protocol). The fine-grained resolve/continue/abort loop never crosses the wire (ADR §E). Heartbeat rides WS Ping/Pong frames, not JSON.
2. **`lumina-companion`** (lib + thin bin; depends on **protocol only — never core/db**): `git/` holds the `GitBackend` `#[async_trait]` with engine-neutral types only (`Sha`, `WorktreeState`, `WorktreeStatus`, `MergeResult`, neutral `GitError`, semantic `ResolveOp::{TakeOurs, TakeTheirs, StageResolution, Continue, Abort}`) — modelled on the `DbClient`/`AppError` erased seam; `ShellGit` (tokio::process + the Research-Note-14 hygiene in one `base_command()` helper) implements it; **`run_git` is an inherent method on `ShellGit` only** (quarantined off the migratable trait surface, doc-marked audited/last-resort); `FakeGitBackend` is the neutrality proof and the executor's test double. `executor.rs` maps Intent→backend→Outcome and owns the merge choreography: ensure/lazily-create the companion-managed integration worktree (User Decision 1) → self-heal a persisting `MERGE_HEAD` from any interrupted merge (`abort_merge` first) → verify clean (makes `--abort` deterministic, Note 10) → record pre-merge tip → merge → on conflict: abort + `Conflicted` → on success: reachability gate (`--is-ancestor` per SHA, Note 12) → **on gate violation: `reset --hard` to pre-merge tip + `Failed`** (the SHA-stability outcome gate, ADR §H). `connection.rs` dials with `connect_async`, sends Hello, then `tokio::select!`s heartbeat ping/deadline vs inbound intents; hand-rolled exponential backoff redial; exits when the parent-spawned process's WS permanently fails (its natural lifecycle signal).
3. **`lumina-server`** (gains a dep on `lumina-protocol` ONLY — zero git deps stays linker-enforced): new `companion/` module = the protocol-client seam: `CompanionRegistry` in `AppState` (default-constructed empty, mirroring `pty_register_tx: None`) holding the WS send channel, a pending map `RequestId → oneshot::Sender<Outcome>`, and the in-memory merge-lease map; on disconnect it **drains all pending oneshots with a disconnect error and voids leases**; on (re)connect it auto-sends `Reconcile`. WS endpoint `GET /api/companion/ws` (absent Origin accepted; the handler MUST reject non-loopback peers via `ConnectInfo<SocketAddr>.ip().is_loopback()` — the `HOST` env var (app.rs:108-114) permits 0.0.0.0 exposure and the sessions/ingest "posture" is doc-only, not code; this channel drives git execution and store mutation). The `execute_worktree_merge` MCP tool + `POST /api/worktrees/{id}/execute-merge` mirror: **pre-flight first** (worktree exists; owning sprint `effective_status == review`; companion `Hello.repo_root` matches the project's primary repo_link `local_path` when set; `branch` non-null AND target resolvable (`base_ref` non-null OR explicit `target_branch` param) — else 422; avoids the git-mutated/store-not split-brain and wrong-repo merges) → derive `must_remain_reachable` via a new read-only repo fn (UNION of the `task_commits.sprint_id` path and the `sprint_tasks`-junction path across sprints sharing `worktree_id` — the nullable-`sprint_id` trap) → acquire lease → `registry.execute(intent)` → on `Merged`/`AlreadyUpToDate`: call the EXISTING `repo::record_worktree_merge` with the ground-truth SHA → release lease. On `Conflicted`: release lease, return the structured conflict for the **caller** to surface as open-question/finding (no automatic DB write — record-only + no-merge-supervisor-yet). Companion-unavailable maps to an error at the handler layer (no new core `AppError` variant). `AlreadyUpToDate` makes a re-run after a mid-merge disconnect idempotent (ground truth = git).

**Co-launch** (`--with-companion`, `--companion-bin`): clap flags on the bare invocation in `cli.rs`; spawn `lumina-companion` via `tokio::process::Command` with `kill_on_drop(true)`, holding the `Child` across `serve().await` in `cli::run` — the binary entrypoint layer, never `app::serve` (ADR co-launch rule). Default path = sibling of `current_exe()`; emit an actionable error if absent (a bare `cargo run -p lumina-server` won't have built it).

**Rejected/Deferred** (beyond the ADR's own list): durable lease table (User Decision 3); public triggers for the other four intents (User Decision 4); `backon` dep for backoff (hand-roll, Note 6); copying the pty WS Origin allowlist (breaks non-browser clients).

## Risks

- **Split-brain (git mutated, store not)** — companion merges but `record_worktree_merge` would reject. *Mitigation*: pre-flight the `review`-status + branch checks BEFORE lease/dispatch (T7 ordering); `AlreadyUpToDate` outcome makes post-disconnect re-runs idempotent; reconnect auto-Reconcile reports ground truth.
- **WS e2e flakiness** — first ephemeral-listener test in the repo. *Mitigation*: bind port 0, deterministic connected-notification (watch channel) instead of sleeps, in-process companion (no process spawn), sequential single-intent execution.
- **Windows shell-git test fragility** — CRLF, longpaths, missing identity. *Mitigation*: test-repo helper pins LF + sets identity explicitly; `base_command()` hygiene applies `core.longpaths` per call; tests require git on PATH (already true for the dev machine; documented in T10).
- **Orphaned companion on parent crash** — `kill_on_drop` only covers in-process drop. *Mitigation (accepted v1)*: companion self-terminates when its WS connection permanently fails; documented limitation, no OS job-object work in 1b.
- **Nullable `sprint_id` undercounts `must_remain_reachable`** — a join on `task_commits.sprint_id` alone silently drops rows. *Mitigation*: T7's UNION query via the `sprint_tasks` junction; e2e records commits through both paths.
- **Count-gate/annotation churn** — the new tool must land in the membership list, two count asserts, and the annotations loop or tests panic. *Mitigation*: enumerated explicitly in T7's acceptance.
- **Protocol skew later** — v1 has no versioning story beyond equality. *Mitigation*: Hello carries `PROTOCOL_VERSION`; server refuses mismatch loudly; pinned-JSON snapshot tests (T1) make accidental wire breaks fail CI-side.
- **Trait-surface gaps discovered mid-executor** — *Mitigation*: the trait surface is frozen at Task 2 (it includes `reset_hard`); a gap discovered during T4 is surfaced to the orchestrator and fixed between waves — never patched mid-wave while T3 implements the trait in parallel.
