# Plan: tomlctl task DAG store (`tasks.toml`) with graph verbs and carrier adoption

**Plan path**: `docs/plans/whimsical-hugging-puppy.md`
**Created**: 2026-09-07
**Status**: Draft

## Context

A plan's `## Tasks` section is the largest single thing an orchestrator loads: 50–86 KB (roughly 12–22k tokens) for the 23–68-task plans in the reportdesignkit corpus, and 60 KB for the largest dev-tools plan. Only ~2 KB of that is the DAG (ids, titles, files, edges); the rest is per-task prose that only the agent executing that task needs. Today `/implement` re-derives the frontier, file-claim intersections and checkpoint closures in prose every run, `/review-plan` re-checks them by hand, and planners hand-widen marker edges so that "closure of marker = milestone group" (`studio-polish.md` widens 12→3,8,9,11 and 27→19,23,24,25,26 purely to make the cut rule hold). `docs/ideas/plan-flow-mechanical-verification.md` measured that 36% of one executed plan's tasks sat in no marker's closure and were committed only by the final train.

This plan adds a per-flow `tasks.toml` store to `tomlctl` with a `tasks` verb group: import from the house markdown format, add/update rows, query with the existing `--where/--select/--pluck` surface, and compute ready-sets, Kahn batches, closures, chains and checks mechanically. From `/plan-new` Phase 9 onward the store is canonical and the plan's `## Execution Policy` / `## Tasks` / `## Dependency Graph` sections are rendered from it, the same derive-don't-author pattern `PROGRESS-LOG.md` already follows. `/implement`, `/review-plan` and `/plan-update` consume it, and implementing agents fetch task context by id instead of receiving pasted text.

Lumina is parked; tomlctl is the primary task store for the foreseeable future. Sub-agent write verbs with execution-record audit types, and the ratatui `tasks watch` viewer with its herdr pane launch, are deliberate follow-up plans.

## Scope

- **In scope**: `tomlctl tasks` verb group (`import-plan`, `add`, `add-many`, `update`, `show`, `list`, `edges`, `ready`, `batches`, `closure`, `check`, `render`); the `tasks.toml` schema and graph engine; `tasks` as the fifth canonical flow artifact (init, resolve, doctor, ensure-artifact, envelope); a new `flow-contract-task-store` skill plus `tomlctl` skill reference; contract updates (plan-output-format, plan-restructure, execution-record-schema, flow-context, bootstrap template/agent); carrier adoption in `/plan-new`, `/implement`, `/review-plan`, `/plan-update`; README/capabilities parity and the minor version bump; tests and golden fixtures.
- **Out of scope**: sub-agent write verbs (`tasks note/touched/discover`) and new execution-record audit types; the `tasks watch` TUI and herdr launch hook; `/tdd`'s own carrier text (it does not read `## Tasks`) — but `/tdd` dispatches `/implement --flow <parent>-tdd-<NNN>` against a one-task mini-plan whose `task_ref` is pinned to `tdd-cycle-<NNN>-<short-name>` (`claude/commands/tdd.md:52,65,93,99`), so task 33 MUST exempt tdd sub-flows from the store skip-list (record-derived, no auto-import); lumina coupling; the multi-file `00-outline.md` plan layout (specified but unused in both corpora); `[tasks].completed` derivation (unchanged, still from the execution record).
- **Affected areas**: `tomlctl/src/tasks/` (new), `tomlctl/src/cli/`, `tomlctl/src/flow/`, `tomlctl/src/io.rs`, `tomlctl/src/main.rs`, `tomlctl/Cargo.toml`, `tomlctl/tests/`, `tomlctl/README.md`, `claude/skills/`, `claude/commands/`, `claude/agents/flow-bootstrap.md`, `scripts/templates/flow-context.md`, `CLAUDE.md`.

### Agent 1 — toml / clap / regex behaviour (research-lite)

- **R1 (high)** `toml` 1.1.4 emits `"""` multi-line basic strings for any string containing `\n`; `to_string` and `to_string_pretty` are identical for strings — `pretty` toggles only `multiline_array` (`toml_writer-1.1.2/src/string.rs:35-46 as_default`; `toml-1.1.4/src/ser/style.rs`). *Impact*: paragraph task bodies in `tasks.toml` are readable with no custom serializer.
- **R2 (high, corrected in review)** With a newline present, `as_default` never reaches the single-line escaped form: the selection order is `as_basic_pretty → as_literal → as_ml_basic_pretty → as_ml_literal → (newline ? as_ml_basic : as_basic)`. A backslash sets `escape` only (not `escape_codes`), so a multi-line body containing `\` or >2 consecutive `"` is emitted as a `'''` multi-line LITERAL string; an ASCII control char (incl. `\r`) sets `escape_codes` and lands on `"""` multi-line basic with the control char escaped (`toml_writer-1.1.2/src/string.rs:35-46,88-96,355-372`). *Impact*: still normalise bodies to LF before writing; and golden TOML fixtures (tasks 24/25) must expect `'''` delimiters for any body containing a backslash — this plan's own task bodies do.
- **R3 (high)** A nested array of tables serialises as `[[items.coupling]]` blocks, never inline; an empty one emits `coupling = []` (`toml-1.1.4/src/ser/document/strategy.rs:243-247`). *Impact*: `coupling = [{to=7, reason=…}]` will not round-trip inline — flat arrays chosen (User Decisions Q2).
- **R4 (high)** `preserve_order` backs maps with `IndexMap`, whose iteration order is insertion order (`RandomState` affects buckets only), so parse and serialise preserve key order deterministically (`toml-1.1.4/src/map.rs:11-13,43`). *Impact*: stable field order, minimal diffs, no sort step.
- **R5 (high)** Only parse bound is recursion depth 80 (`toml-1.1.4/src/de/parser/mod.rs:36-71`); no size limit. *Impact*: a 70-task store is unconstrained.
- **R6 (high)** clap 4.6 creates an implicit `ArgGroup` per `Args` derive (id = struct name); duplicate ids in one `Command` debug-assert-panic; flattening one shared struct into *different* subcommands is safe (`clap-4.6.6/src/_derive/mod.rs:197-210`). *Impact*: `QueryArgs` can be flattened into `tasks list` unchanged.
- **R7 (high)** `#[command(flatten)]` accepts only `next_help_heading`; cross-flatten `conflicts_with` must live on the field or `#[group]` inside the shared struct (`_derive/mod.rs:184-187`). *Impact*: prefer post-parse validation for verb-specific conflicts.

commit_granularity = "per-task"   # per-task | per-checkpoint | single-commit

Only `needs` and `coupling` are stored edges. `overlap` (two tasks sharing a file with no dependency path), checkpoint closures, marker `after` lists and the `Checkpoint after` bullet are computed on every read and never persisted — the never-mirror principle applied to the store itself. The array is `items` so the existing `[[items]]` machinery and `QueryArgs` apply; the store lives under `.claude/`, so `guard_write_path` holds and `mutate_doc` gives the exclusive lock, sidecar and seed for free. Bodies are LF-normalised before every write (R2); bodies containing a backslash serialise as `'''` literal strings, which golden fixtures must expect.

### Verb surface (`tomlctl tasks …`)

Every verb takes a shared, **non-required** `--slug <slug> | --file <path>` target group (mutually exclusive): `--slug` resolves `<root>/.claude/flows/<slug>/tasks.toml` via `TOMLCTL_ROOT` / git top-level exactly as `flow render-progress-log` does. `import-plan` may run with `--plan <path>` alone (plan-mode validation); every other verb rejects an empty target in post-parse validation with a `kind=validation` error, because clap's own missing-required error is invisible to `command_lint`. Read verbs honour `--verify-integrity`, write verbs the write-integrity flags (write verbs go through `mutate_doc`, so `--allow-outside` applies to `--file` targets outside `.claude/`).

| verb | kind | output |
|---|---|---|
| `import-plan [--plan <path>] [--reconcile-record] [--dry-run]` | write (upsert by `ref`) | `{ok, added, updated, unchanged, removed_refs[], added_refs[], adopted_refs[], unmatched_refs[], findings[]}` |
| `add --title --effort --files a,b --needs 1,2 [--coupling] [--deps-note] [--checkpoint] --action/--action-file …` | write | `{ok, id, ref, batch}` — rejects dangling targets and cycles before writing |
| `add-many --ndjson -` | write | one row per line, same validation, all-or-nothing |
| `update <id> [--status] [--agent] [--commit] [--checkpoint] [--set k=v]…` | write | `{ok, id, changed[]}` — `ref` immutable unless `--ref` |
| `show <id> [--with body,files,deps,dependents,summary]` | read | one JSON object; default `summary` = id, ref, title, effort, status, checkpoint, files, needs, coupling |
| `list` (+ flattened `QueryArgs` + an explicit `--count`) | read | rows / pluck / count / count-by exactly like `items list` |
| `edges [--kind needs\|coupling\|overlap] [--dot]` | read | edge list; `--dot` for a later Graphviz render |
| `ready [--in-flight 3,4]` | read | `{ready[], held[{id, blocked_on_file, holder}], next[]}` |
| `batches` | read | Kahn layers, each sorted ascending |
| `closure --checkpoint A` / `closure --task 12 --up\|--down` | read | sorted id set plus the group's maximal elements |
| `check [--plan]` | read | findings with `class`, `severity` (`error`/`warning`), ids; exit 1 on any `error` |
| `render [--stdout] [--check]` | derived write | rewrites the plan's `## Execution Policy`, `## Tasks`, `## Dependency Graph` sections in place; `--check` exits 1 on drift without writing |

`check` classes: `dag/cycle` (error, members), `dag/dangling-ref` (error), `dag/duplicate-number` (error), `dag/unreachable-claim` (warning: shared file, no directed path either way), `checkpoint/orphan-task` (warning: `checkpoint = ""`), `checkpoint/invalid-cut` (error: the union of groups A..K is not downward-closed), `checkpoint/marker-mismatch` (warning: the `Checkpoint after` bullet disagrees with the markers' derived maximal elements at import), `policy/max-parallel-range` (error), `plan/orphan-row` (warning: a store row whose `ref` is absent from `last_import_refs` — a renamed or deleted task; `error` when its `status` is not `pending`, since `render` would otherwise resurrect it into `## Tasks` and it inflates `[tasks].total`). With `--plan`, `render/drift` (warning) when the markdown sections differ from the render output after line-ending normalisation. `files/closure` is deliberately absent (68% false-flag rate measured).

### Graph engine (`tomlctl/src/tasks/graph.rs`)

Self-contained: takes `&[Node{id, files, needs, coupling, status, checkpoint}]`, builds dense indices, and offers `kahn_rounds()`, `cycle_members()`, `closure_up(id)` (transitive dependencies — ancestors — inclusive), `closure_down(id)` (transitive dependents — successors — inclusive), both via `Vec<[u64;4]>` bitsets (hard cap 256 nodes, error above), `frontier(in_flight)`, `overlap_pairs()`, `groups()` (ordered by `[[checkpoints]]`; validity = each prefix union is a lower set under `closure_up`; `after` = maximal elements). Deterministic everywhere: ascending id tie-breaks (R13). No dependency added.

### Importer (`tomlctl/src/tasks/markdown.rs`, `parse_tasks.rs`, `parse_policy.rs`, `import_plan.rs`)

Line-oriented, anchored on `## Tasks` (to the next `^## `). **Line endings**: the whole corpus is CRLF on disk, so `sections()` strips one trailing `\r` from every line before any matching and every parser sees LF-only input. Task heading: `^#{3,4} ([0-9]+)\. (.+?)( \[([A-Za-z-]+)\])?( — .*)?$`; non-integer ids and effort tags outside `S|M|L` are errors naming the line; other h3/h4 headings inside the section are phase labels and skipped. Field lines `^- \*\*(Files|Depends on|Blocked-by|Blocked by|Action|Detail|Acceptance|Effort)\*\*:` with continuation = following lines indented ≥2 spaces (until the next field, heading, or blank line followed by a heading). Files: strip backticks, split on commas, trim, drop trailing parentheticals like `(new)`, drop `none`. Depends on: `—`/`none`/empty → `[]`; leading comma-separated integers → `needs`; the parenthetical remainder → `deps_note`. `## Execution Policy`: first token of each `- **Label**:` value (the `Checkpoint after` list is parsed for the mismatch check only and never feeds membership), remainder → `policy.note`. `## Dependency Graph` **only** is fed to `parse_markers` (markers duplicated inside `## Tasks` are ignored); markers matched after stripping `*`, `-`, `—`: `CHECKPOINT ([A-Za-z0-9]+) after tasks? ([0-9][0-9, –-]*)` with `–`/`-` ranges expanded; membership on import = closure of the marker set minus earlier groups (so legacy plans import with the semantics `/implement` gives them today); the remainder of the marker paragraph → `rationale`, with a trailing `(INVALID CUT)` stripped so it is never persisted. All regexes use ASCII classes (R9) and a unit test compiles every pattern, including one negated case. Import is an **upsert keyed by `ref`**: existing rows keep `status`, `agent`, `commit` and the record-adopted `ref`; new rows are `pending`; nothing is deleted, and the resulting ref set is stored as `last_import_refs` so `plan/orphan-row` can detect renamed or deleted tasks; the envelope reports `added_refs` / `removed_refs` so carriers can gate on a ref-set diff. `--reconcile-record` reads `execution-record.toml` task-completions, marks matches `done`, adopts the record's ref on a unique normalised match, and reports the rest as `unmatched_refs`. The store's `plan_path` is seeded from `context.toml` on import (or from `--plan` under `--file`).

### Renderer (`tomlctl/src/tasks/render.rs`)

Pure `render_sections(&Store) -> Rendered{policy, tasks, graph}` plus an in-place section replace through `markdown.rs` (each `## X` section runs to the next `^## `; missing sections are inserted in canonical order — Execution Policy before Tasks, Dependency Graph after Tasks). `## Execution Policy` renders the four bullets, with `Checkpoint after` derived as the union of every group's maximal elements (never stored) and `policy.note` appended as trailing prose. `## Tasks` renders `### N. Title [E]` and the five field lines with bodies re-indented two spaces; `Depends on` lists `needs ∪ coupling` sorted, then `(deps_note)`. `## Dependency Graph` renders the preamble sentence and one marker per group: `— CHECKPOINT A after tasks <maximal elements> — closure: <sorted ids>. <rationale>`, with `(INVALID CUT)` appended for a group whose `valid_cut` is false. `render_into_plan` detects the source document's dominant line ending and re-applies it to the replaced sections, so a CRLF plan is not rewritten to mixed endings and `check_render_drift` (which compares after normalisation) does not report permanent drift. The target path is resolved from `context.toml` under `--slug` and from the store's `plan_path` under `--file`, never from a free argument — and that is **not** containment on its own (`flow init` does not validate `--plan`; `atomic_write` runs no guard), so `render` additionally rejects an absolute path, any `ParentDir` component, and any canonicalised target outside `repo_or_cwd_root()`, mirroring `render_progress_log.rs`'s `title_from_context` checks, and refuses with `kind=validation` rather than falling back. Written with `atomic_write` and no sidecar like `PROGRESS-LOG.md`. Round-trip invariant `import(render(store)) == store` (ids, refs, needs, coupling, checkpoints, rationale, policy) is a golden test.

## Risks

- **Scope (~50 unique files) exceeds the ~25 guard** — mitigated by the user's explicit choice, three checkpoints, and every task except the scaffold and three inseparable four-file tasks staying ≤3 files; if milestone C slips, A+B still ship a usable `tomlctl tasks` with markdown-canonical plans.
- **`ref` divergence from historical `task_ref`s** re-executes completed tasks on a resumed flow — mitigated by `--reconcile-record` adoption on import (task 17), the ref-set diff gate on every re-import (tasks 33, 34, 35), the contract pin (task 31), and the `/tdd` exemption; residual `unmatched_refs` are surfaced, never guessed.
- **Doctor tolerance for a missing `tasks` key** is a deliberate asymmetry (other keys still hard-fail; an extra key was never detected) — mitigated by unit and black-box tests in tasks 21/22 asserting both behaviours and that no `context.toml` bytes are written.
- **Renderer writes outside `.claude/`** (the plan file) — mitigated by sourcing the path only from `context.toml` or the store's seeded `plan_path`, explicit absolute/`ParentDir`/under-root rejection (task 19), `atomic_write`, `--check`/`--stdout` paths, and the golden test asserting bytes outside the three sections are untouched and that an escaping path is refused.
- **CRLF corpus** — the whole `docs/plans/` tree is CRLF on disk; mitigated by stripping on read, re-applying the dominant ending on write, normalising in the drift check (tasks 14, 18), and the CRLF fixture variants plus the corpus smoke test.
- **Importer strictness vs. corpus drift** (`12a`, `M-leaning-L`) — mitigated by errors that name the line and the corpus smoke test's asserted allowlist (task 26); legacy plans that cannot parse keep working under today's markdown path until fixed by hand.
- **Stale installed binary** — carriers invoke `tomlctl` from PATH and `command_lint` cannot see it; mitigated by installing before checkpoint C commits and by `/implement`'s degradation rule.
- **Prompt-cache regression in `/implement`** if the fetch-by-id prompt breaks the byte-identical preamble — mitigated by keeping the preamble verbatim and appending the id/fetch block after it (task 33).
- **No way back from milestone C** — the carrier rewrites delete the prose frontier, file-claim gate and skip-list, so a store that exists but misbehaves leaves `/implement` with no fallback; mitigated by the degradation rule in task 33 (halt with a named diagnostic, `cargo install --path tomlctl`, `git revert` of the four carriers) rather than proceeding on partial store output.
- **Write amplification on Windows** — `tasks update` at dispatch/return/failure plus step-3c `tasks add` turns a 36-task `/implement` run into ~100 TOML+sidecar renames against a recorded transient `os error 5` on `tmp.persist` under AV/indexer contention; mitigated by the bounded persist retry in task 6 and `tomlctl integrity refresh` documented as the recovery step in the task-store contract.
- **Hand edits to `## Tasks` after the store is canonical** — mitigated by `render --check` before every render in `/implement` and `/plan-update`, and the ref-set gate on re-import.
- **Transient dead-code warnings inside milestone A** — leaf modules land before dispatch wires them; acceptable within a checkpoint window, and the window's tip clippy run is the gate; per-task acceptances therefore assert only "no warning naming a file this task edits".
