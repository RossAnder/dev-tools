# Plan: tomlctl pattern-finding support — `sweep`, `items sweep`, `items clusters`, `items orphans` over instances

**Plan path**: `docs/plans/tomlctl-items-sweep-clusters.md`
**Created**: 2026-09-17
**Status**: Review

## Context

On 2026-09-17 the research method gained pattern findings: a finding whose fix repeats at many sites now carries `instances` (every site as `file:symbol`), `sweep` (the search strings that found them) and `enumeration` (`complete` | `incomplete`), and the apply flow budgets on that declared file set instead of a numeric cap. Three steps in that design are still orchestrator prose performed by hand on every run: re-running an item's sweep strings (vet step 4 and apply pre-analysis), grouping selected items into file-disjoint clusters ordered by `depends_on` (apply Step 3 plus the dependency-sort skill's Kahn pseudocode), and checking that an item's anchors still resolve (`items orphans` today checks only `file` and `symbol`). Each is deterministic, and each is where instances get dropped or miscounted when a model transcribes them. This plan moves them into `tomlctl`, so the agents, the vet pass and the apply flow share one enumerator and one clusterer, and the prose skills describe what to call rather than what to compute.

## Scope

- **In scope**: a standalone `tomlctl sweep -e <regex>…` verb over tracked files; `tomlctl items sweep <ledger>` that re-runs each item's stored `sweep` strings, diffs against `instances`, and optionally writes back with `--update`; `tomlctl items clusters <ledger> --ids …` emitting file-disjoint clusters, dependency batches and a per-cluster lite file-scope flag; an `instance-missing` class in `items orphans`; the shared foundations they need (tracked-file enumeration, anchor parsing, union-find extraction, a `pub(crate)` Kahn core, a bytes-regex compile helper); one new direct dependency, `memchr` (already in the lock graph through `regex`, so `cargo audit` sees nothing new); a deliberate tightening of `items list --where-regex` to the same 512-byte pattern cap the sweep enforces; tests, README, capability registry, version bump to 0.9.0; the skill and reference prose that names the manual procedures these verbs replace; and the three schema-hardcoding callouts that name `items orphans` and `items find-duplicates` as the closed pair of ledger-schema-specific verbs, which the two new `items` verbs join.
- **Out of scope**: any change to the research agents' output contract or the ledger field vocabulary (already landed); a parser for agent finding records; `ignore`-crate walking or non-git trees; submodule recursion; a `--file-budget` removal (the flag stays for undeclared items); carrier commands (`review.md`, `optimise.md`) beyond what the skills they invoke already say — `claude/commands/review-plan.md` is the one carrier edited, and only its schema callout.
- **Affected areas**: `tomlctl/src` (new `repo_files.rs`, `anchor.rs`, `union_find.rs`, `sweep.rs`, `items_sweep.rs`, `clusters.rs`; edits to `main.rs`, `orphans.rs`, `query.rs`, `backlog/cluster.rs`, `tasks/graph.rs`, `tasks/mod.rs`, `cli/types.rs`, `cli/dispatch.rs`), `tomlctl/tests` (new `sweep.rs`, `clusters.rs`; edit `capabilities.rs`, `common/mod.rs`), `tomlctl/Cargo.toml`, `tomlctl/Cargo.lock`, `tomlctl/README.md`, `claude/skills/tomlctl/**`, `claude/skills/flow-contract-apply-pipeline/**`, `claude/skills/flow-contract-apply-dependency-sort/SKILL.md`, `claude/skills/flow-contract-vet-research/SKILL.md`, `claude/skills/flow-contract-ledger-disposition-sweep/SKILL.md`, `claude/skills/flow-contract-ledger-schema/SKILL.md`, `claude/skills/flow-contract-execution-record-schema/SKILL.md`, `claude/skills/tomlctl/references/tasks-store.md`, `claude/commands/review-plan.md`, `claude/skills/research-methods/references/codebase-review.md`.

## Research Notes

Vetted 2026-09-17 (two `research-lite` lenses; 7 of 17 findings spot-checked by command, none dropped). `[[vet_events]]` append deferred to Phase 9 (no ledger exists in plan mode).

### Repository file enumeration (Agent 1)
- **`git ls-files --full-name -z --cached --others --exclude-standard`, run with `git -C <toplevel>`** — high. Paths are cwd-relative without `--full-name` (probe: `backlog/add.rs` vs `tomlctl/src/backlog/add.rs`); `-z` emits verbatim NUL-terminated names, so split on `\0`. Resolve each path against the `git rev-parse --show-toplevel` root `io::repo_or_cwd_root` already caches. Source: git-scm.com/docs/git-ls-files, verified by probe. Impact: zero new dependencies for enumeration.
- **Non-git directory: exit 128, `fatal: not a git repository`** — high (probe). Sweep must return a tagged error, not panic; treat any non-zero exit as the branch. A warning at exit 0 (dangling directory symlink) is a separate branch: git continues past the subtree, so the enumeration is silently short.
- **`--cached` lists index entries, not disk files** — high. A staged-but-deleted file or a submodule gitlink appears and `fs::read` fails; skip `NotFound` / `IsADirectory` silently. `--recurse-submodules` cannot combine with `--others`; no `.gitmodules` here, so document the limit.
- **`ignore` 0.4.33 alternative** — medium. About 7 genuinely new crates (`ignore`, `crossbeam-deque/epoch/utils`, `same-file`, `walkdir`, `winapi-util`); parses `.gitignore` itself, `require_git` defaults true, deterministic order only via the single-threaded `Walk`. Kept in reserve; the sweep runs on a repo by definition.
- **Binary detection: NUL byte in the first 8 KiB**, ripgrep's heuristic, via `memchr 2.8.3` — high. The crate is already in the lock graph through `regex` but is not a direct dependency and is not re-exported, so `memchr = "^2"` must be added to `[dependencies]`; `cargo audit` sees no new crate. UTF-16 files skip, as in ripgrep.
- **Prefer `regex::bytes` over `from_utf8_lossy`** — medium. Lossy decoding reallocates and shifts offsets on invalid bytes; bytes regexes search `&[u8]` in place.
- **CRLF is the live case**: `core.autocrlf=true` here, worktree CRLF with LF index — high (probe). Split on `\n`, strip one trailing `\r` before matching, report the 1-based `\n` index.
- **Git for Windows emits forward slashes**; `core.longpaths` unset so >260-char paths can fail at enumeration, a git-side gap — medium.
- **Size guards have no ripgrep precedent** (no default `--max-filesize` / `--max-count`) — high. Pick a tomlctl policy: per-file byte cap and total-hit cap, stated as ours.

### regex 1.13.1 / clap 4.6.6 / serde_json 1.0.151 (Agent 2)
- **`RegexSet`, `RegexSetBuilder`, `regex::bytes::Regex` are ungated** under `std`+`perf` — high (vendored `src/builders.rs`). A set prefilter per file is available.
- **Unicode is off in the shipped binary and `(?-u:…)` is mandatory**: `\b`, `\w`, `\d`, `\s`, `(?i)` on non-ASCII fail to compile — high. **Orchestrator addendum (verified)**: `cargo tree -e normal,features -i regex` shows only `perf*` for the binary, but the default `cargo tree` shows `regex/default` unified in through `predicates` (dev-dependency of `assert_cmd`), so `cargo test` builds have Unicode and the installed binary does not. Tests must not rely on `\w`-style syntax, and the sweep's compile error must name the `(?-u:…)` rewrite.
- **`RegexBuilder::dfa_size_limit` forwards to `hybrid_cache_capacity`** (a lazy-DFA cache knob, default 2 MiB), not a safety bound; `size_limit` → NFA size limit (default 10 MiB, query.rs tightens to 1 MiB) is the real one — high (`builders.rs:189-192`, verified). Reuse `query.rs:90 compile_user_regex` and correct its comment; bound pattern length too — not because matching is super-linear (the crate guarantees linear time) but because a long pattern can thrash the lazy-DFA cache under the 1 MiB `dfa_size_limit`.
- **`RegexSetBuilder` exposes the same three limits** — high.
- **Line numbers: one `find_iter` over the whole file plus a `memchr_iter(b'\n')` offset table and binary search per hit**; set `.multi_line(true).crlf(true)` so `$` does not match after a `\r` — high (`builders.rs` `crlf` doctest, verified present). `crlf(true)` also stops `.` matching `\r`, and `^`/`$` never match between `\r` and `\n`, so a pattern is not portable between the sweep helper and `compile_user_regex`, which sets neither flag. Per-line `is_match` defeats the `perf-literal` prefilter.
- **clap idioms all work under `default-features=false`**: `#[arg(long, value_delimiter = ',')] ids: Vec<String>` (in-repo precedent `types.rs:1872`), `#[arg(short = 'e', long = "pattern")] pattern: Vec<String>` (derive infers Append), `#[arg(long)] update: bool` beside a flattened `WriteIntegrityArgs` with no long-name clash — high. A field with no `#[arg]` attribute is a positional.
- **`serde_json` `Map` is an `IndexMap`** under `preserve_order`: insertion-ordered, so sort hits explicitly before building output — high (`map.rs:23-27`).

## Approach

**One enumerator, three consumers.** A single engine in `tomlctl/src/sweep.rs` compiles patterns, walks the tracked-file list, and returns sorted `file:line` hits. The standalone `tomlctl sweep` exposes it to research agents so an `Instances` line is produced by the tool rather than transcribed from Grep output; `items sweep` binds it to a ledger item's stored `sweep` strings and diffs against `instances`; the vet pass and the apply pre-analysis call `items sweep` instead of re-running searches by hand.

**File enumeration** (`tomlctl/src/repo_files.rs`): `git -C <root> ls-files --full-name -z --cached --others --exclude-standard`, root from `io::repo_or_cwd_root` (`tomlctl/src/io.rs:1498`), split on `\0`, sorted, deduplicated, then filtered: the ledger being swept, everything under `.claude/`, and `docs/plans/**` are dropped, because an item's `instances` and `sweep` arrays are stored verbatim there and every pattern would otherwise match its own record (the exclusions are a default `--exclude` list the caller may extend). Non-zero exit is `ErrorKind::Other` tagged "not a git repository" with the stderr tail. Entries that are directories or unreadable at scan time (staged deletes, gitlinks) are counted under `skipped.unreadable`, never fatal. Each path is checked through `io::path_under_root` (`tomlctl/src/io.rs:1541`) before it is read, so a symlink resolving outside the root is skipped rather than read and echoed; a non-empty git stderr at exit 0 (a dangling directory symlink makes git warn and continue) is surfaced as `skipped.unenumerated` and clears `coverage_complete`.

**Search semantics** (`tomlctl/src/sweep.rs`): patterns compile through a new `query::compile_user_bytes_regex` beside `compile_user_regex` (`tomlctl/src/query.rs:90`), sharing `REGEX_COMPILE_SIZE_LIMIT` and `REGEX_DFA_SIZE_LIMIT`, built with `.multi_line(true).crlf(true)`, plus a pattern-length cap. A compile failure names the `(?-u:…)` rewrite in its message because the shipped binary has no Unicode tables. Each file is read as bytes; a NUL in the first 8 KiB marks it binary (`memchr`, added as a direct dependency); files over `--max-file-bytes` (default 4 MiB) are skipped and counted. One `find_iter` per pattern over the whole buffer; byte offsets map to 1-based lines through a `memchr_iter(b'\n')` table with binary search. Hits are `{file, line, pattern}` keyed by canonicalised path (this repo mirrors `claude/agents` and every `claude/skills/<name>` under `.github/` through directory symlinks that git holds as ordinary blobs), so one file reachable by two paths is reported once, then sorted by file then line then pattern index; hits collapsing to the same `file:line` across patterns and repeated matches on one line are emitted once; a `--max-hits` cap (default 5000) over distinct sites sets `truncated: true` rather than erroring. Output also carries `files_scanned`, `skipped: {binary, oversize, unreadable, unenumerated}` and `coverage_complete` (true only when nothing at all was skipped — binary skips count, because a skipped file can hide a site).

**Ledger binding** (`tomlctl/src/items_sweep.rs`): run the engine once over the union of every selected item's `sweep` strings, attributing each hit back to its item by pattern index, then compare at anchor granularity: a hit in a recorded file whose line matches no recorded `file:line` anchor and lies outside every recorded `file:symbol` anchor's line is `new`, so growth inside an already-recorded file is visible; file-level `recorded`/`found` sets are reported alongside for the apply flow's file budget. Report `new` (as `file:line`), `gone` (recorded anchors whose file was searched and has no hit), `kept`, and `unverified` (recorded anchors whose file was skipped or lies past a `--max-hits` cut). `--update` refuses when `truncated` is true or `unverified` is non-empty, since absence of a hit is not evidence there. Symbol anchors among `kept` are additionally checked for presence with the orphans word-boundary regex, and a missing symbol is reported under `gone` with `reason: symbol-missing`. `--update` builds one `MutationPlan` through `items::compute_apply_mutation` (`tomlctl/src/items.rs:1254`) and `io::mutate_doc_plan` (`tomlctl/src/io.rs:883`) that rewrites `instances` as kept anchors followed by new `file:line` anchors; `enumeration` is left untouched, because completeness is the agent's judgement about forms the regexes cannot reach, and the tool instead reports `coverage_complete`. `--dry-run` reuses `output::emit_dry_run_plan`. Items without a `sweep` array are listed under `skipped_items` with `reason: no-sweep`.

**Anchors** (`tomlctl/src/anchor.rs`): `Anchor { file: String, at: AnchorAt }` with `AnchorAt::Line(u64) | Symbol(String)`, parsed by splitting at the first `:` after the last path separator (`/` or `\`), so `src/a.rs:Foo::bar` yields symbol `Foo::bar` and `C:\x\y.rs:foo` keeps its drive letter. All-digit tails are lines. `file` is stored verbatim and re-emitted unchanged. Used by `items sweep`, `items clusters` and `items orphans`.

**Clusters** (`tomlctl/src/clusters.rs`): each selected item's file set is `file` ∪ the files of its `instances`, keyed by canonicalised path. Items are topologically sorted first over `depends_on` restricted to the selection (references to ids outside the selection are dropped and reported under `dropped_deps`, mirroring the dependency-sort contract; an item-level cycle is refused with `ErrorKind::Validation` in the `build_or_refuse` wording before any clustering), then items sharing a file are unioned only within one topo level (union-find lifted from `tomlctl/src/backlog/cluster.rs:295-326` into `tomlctl/src/union_find.rs`, keeping singletons here), matching the contract this verb replaces: dependent same-file items stay in sequential batches. Cluster `A` depends on `B` when any item in `A` lists an item in `B` in `depends_on`; batches then come from `tasks::graph::layered_kahn` (`tomlctl/src/tasks/graph.rs:506`) made `pub(crate)`. `lite_file_scope` is true when the cluster has at most two files, or when the cluster holds exactly one item whose `enumeration` is `complete` (a missing key counts as not complete); a multi-item cluster is never lite on the pattern limb, because the apply gate's "one edit shape across all of them" conjunct is not machine-decidable, and the orchestrator still judges it. Output: `{"clusters":[{"id":"c1","item_ids":[…],"files":[…],"depends_on":["c2"],"lite_file_scope":true}], "batches":[["c1","c3"],["c2"]], "dropped_deps":[{"id":"R5","missing":["R9"]}]}` with cluster ids assigned in first-item order.

**Orphans**: `tomlctl/src/orphans.rs` gains an `instance-missing` class per unresolvable `instances` entry (`{id, class, instance, reason}` with `reason` one of `missing-file`, `symbol-missing`, `io-error`, `outside-repo`, `unparseable` — the same five values tasks 15 and 18 document verbatim), reusing its existing path-safety and caches.

**Registration**: `ItemsOp::Sweep`, `ItemsOp::Clusters`, top-level `Cmd::Sweep` (`tomlctl/src/cli/types.rs:474`, `:1391`) in task 11; `FEATURES` entries `sweep`, `items_sweep`, `items_clusters`, `orphans_instances`, `SUBCOMMANDS` entry `sweep` and version `0.9.0` in task 12, which owns their three gated mirrors. Carriers shell out to the installed binary, so each prose consumer keeps its hand procedure as the fallback for a binary older than 0.9, in the form `claude/commands/optimise.md:51` already uses for `items orphans`.

Rejected: the `ignore` crate (seven new crates for non-git support the tool never needs); rewriting `enumeration` under `--update` (the tool cannot judge unsearchable forms); reusing `tasks::graph::Graph` for clusters (bound to `u32` ids and task fields; only the positional Kahn core is shared); clustering before sorting (two acyclic chains crossing over two shared files produce a cyclic cluster graph and a false refusal, and dependent same-file items lose the commit between them).

## Risks

- **Unicode divergence between test and shipped builds** — `cargo test` unifies `regex/default` through the `predicates` dev-dependency while the installed binary has no Unicode tables (verified with `cargo tree -e normal,features -i regex`; the crate already guards its own patterns against this in `tomlctl/src/tasks/parse_policy.rs` `every_pattern_compiles`, which is the model for task 6's test). Mitigation: task 6's helper rejects nothing extra in tests, but every test pattern uses `(?-u:…)` forms, and the compile error names the rewrite; task 13's integration tests run the real binary, which has the trimmed feature set.
- **Carriers on an older installed binary** — the skills call verbs that exist only from 0.9.0. Mitigation: every rewired skill keeps its hand procedure as the older-binary fallback (tasks 17, 18), and the post-checkpoint step runs `cargo install --path tomlctl`.
- **`git ls-files` gaps** — staged deletes and gitlinks appear in the listing, `core.longpaths` is unset so very deep paths may be omitted by git itself, a dangling directory symlink makes git warn at exit 0 and skip a subtree, and submodule contents are never swept. Mitigation: unreadable entries are counted, not fatal; exit-0 warnings clear `coverage_complete`; the limits are documented in `query.md` (task 15).
- **The sweep matching its own records** — ledgers, the backlog and plan documents store `sweep` strings and `instances` verbatim, and `.github/` mirrors harness prose under a second path. Mitigation: default exclusions for `.claude/**`, `docs/plans/**` and the ledger being swept (tasks 3, 7, 8), canonical-path keying for hits and cluster file sets (tasks 7, 9), and a task-13 assertion that the seeded ledger never appears in `new`.
- **Scope is about 32 files** — above the ~25-file guideline, though the docs wave is mechanical and only tasks 7 and 12 exceed three files, each because a manifest edit is inseparable from the code that needs it. Mitigation: three checkpoints keep each increment bisectable; if Phase C proves noisy it can be deferred to a follow-up plan without leaving the tree inconsistent, since the prose fallbacks remain valid.
- **`items sweep --update` rewriting an agent's symbol anchors as `file:line`** — new sites carry no symbol. Mitigation: kept anchors retain their symbol spelling; only new sites are line-anchored, and the agent or orchestrator may re-anchor them at the next round. Documented in task 16.
- **Union-find extraction changes backlog cluster output** — Mitigation: task 4 keeps the representative rule and passes `keep_singletons = false` for backlog; its existing tests are the regression guard.
