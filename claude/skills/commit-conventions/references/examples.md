# Commit Examples — Good and Bad

Worked examples paired with the SKILL.md rules they exercise. Each "bad" example is followed by the rewritten "good" version and the reason.

---

## Simple fix, no body needed

❌ Bad:
```
Fixed login bug
```
- Past tense ("Fixed").
- Capitalized leading word against default.
- No type.
- Vague — which bug?

✅ Good:
```
fix(auth): reject login attempts with empty password
```
The diff itself will show the check that was added. No body needed.

---

## Feature with non-obvious motivation

✅ Good:
```
feat(parser): cache token positions during initial scan

Re-walking the source for every diagnostic was the dominant cost
on large files (profiled at 60% of total parse time on a 12k-line
fixture). Caching positions during the first pass adds ~3% memory
overhead but cuts diagnostic emission from O(n²) to O(n).

Refs: #842
```

Notes:
- Subject is imperative, lowercase, under 50 chars.
- Body explains *why* (the profiling result), not what (the diff shows that).
- Numeric evidence in the body is gold for future archaeology.

## Breaking change

✅ Good:
```
feat(api)!: replace positional args with options object in `query()`

The positional signature `query(sql, params, timeout, retry)` had
grown to seven parameters with confusing optionality. The options
object form is self-documenting and lets us add fields without
further breakage.

BREAKING CHANGE: `query()` no longer accepts positional arguments
beyond `sql`. Migrate `query(sql, params, 5000)` to
`query(sql, { params, timeout: 5000 })`. A codemod is available at
scripts/codemods/query-options.ts. The old signature will be
removed in v3.0.0; until then it logs a deprecation warning.
```

Both the `!` and the `BREAKING CHANGE:` footer are present. The footer names the migration concretely.

## Pure refactor

✅ Good:
```
refactor(db): extract connection pooling into `PoolManager`

No behavior change. Preparing for #901 which needs to swap pool
implementations at runtime.
```

The body explicitly states "no behavior change" — useful signal for reviewers and for `git bisect`.

## Revert

✅ Good (generated by `git revert`, lightly edited):
```
revert: feat(cache): add Redis-backed query cache

This reverts commit a1b2c3d.

The cache invalidation logic doesn't handle multi-tenant key
collisions; tenants were seeing each other's cached query
results in staging. Reverting until #1023 lands.
```

## Common anti-patterns and their rewrites

### "wip"
❌ `wip`

If the work is genuinely in progress and you want to checkpoint, use `git stash` or a feature branch with `--no-verify`. Don't push WIP to a shared branch.

### "address review comments"
❌ `address review comments`

If reviewers asked for several distinct things, those are several commits:
```
fix(auth): validate redirect URL against allowlist
refactor(auth): extract URL validation into helper
docs(auth): document allowlist format in README
```

If they really were one thing:
✅ `fix(auth): validate redirect URL against allowlist (review)`

### "update deps"
❌ `update deps`

✅ `build(deps): bump axios from 1.6.0 to 1.7.2`

If a Renovate/Dependabot tool generates these, let it write the message — it follows the convention by default.

### "various improvements"
❌ `chore: various improvements`

Multiple types → multiple commits. Split it. If you're tempted to write "various", you have at least two commits in one.

## Tricky cases

### Multi-file refactor that touches several scopes

If the refactor genuinely spans, say, `api` and `db` because it's renaming a shared type, pick the broader scope or omit:

✅ `refactor: rename UserRecord to User across api and db modules`

### Revert of a revert

✅
```
revert: revert "feat(cache): add Redis-backed query cache"

This reverts commit d4e5f6g (which reverted a1b2c3d).

#1023 has landed, so the original cache implementation is safe
to re-introduce. The Redis-side fix is in commit ...
```

### Tiny commit that nonetheless needs a body

A one-line fix can deserve a body if the fix is non-obvious:
```
fix(parser): use === for tag comparison

== returned true for `<a>` vs `<A>` because Node coerces tag
names to lowercase during DOM construction but not during raw
token comparison. Caught by fuzz test in #1144.
```

The diff shows `==` → `===`. The body shows why that one character matters.

## A note on commit count vs commit size

A PR with 12 small, well-scoped commits is easier to review and bisect than the same change in 1 mega-commit. If you're squashing before merge, the convention applies to the squash message, not the individual commits — but a clean intermediate history still helps the author write a clean squash message.

Prefer many small commits during development; let the merge strategy decide what survives.

## Other dialects

### Gitmoji

```
:sparkles: add OAuth2 PKCE flow for mobile clients
```

A new feature; `:sparkles:` is the gitmoji convention for `feat`. Imperative mood and 50-char subject still apply.

### Plain

```
add OAuth2 PKCE flow for mobile clients

PKCE is required by the IETF best-current-practice for native and mobile
clients to prevent authorization code interception. The existing OAuth flow
relied on a fixed client secret, which is not feasible to keep secret on a
mobile device. This change adds the code challenge / code verifier roundtrip
and updates the token exchange endpoint.
```

No prefix; subject + body discipline only (imperative mood, 50/72 wrap).
